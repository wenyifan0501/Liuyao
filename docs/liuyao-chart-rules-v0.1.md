# 六爻排盘规则规范

- 规则版本：`liuyao-chart-v0.1`
- 状态：首版工程约定
- 适用范围：六十四卦纳甲排盘
- 不适用范围：小六爻、梅花易数、八字、紫微斗数

## 1. 文档目的

本规范定义网站第一版六爻排盘引擎必须遵守的确定性规则。相同的原始起卦数据、占测时间、时区和规则版本，必须生成完全相同的卦盘。

本规范只负责“盘怎么排”，不直接规定“事情怎么断”。取用神、旺衰、生克、冲合、应期和现实建议属于后续的占断规则层。

## 2. 规则分层

系统将六爻能力拆成三个互不混淆的层次：

1. **起卦层**：产生六个 6、7、8、9 数值。
2. **排盘层**：计算本卦、变卦、八宫、世应、纳甲、六亲、六神、月建、日辰和旬空。
3. **占断层**：选择用神并判断旺衰、动变、成败、时间和建议。

本规范覆盖前两层。AI 无权改变前两层的计算结果。

## 3. 通用数据约定

### 3.1 爻序

所有数组、位图和内部计算均采用从下到上的顺序：

| 数组下标 | 爻位 | 中文名称 |
| --- | --- | --- |
| 0 | 1 | 初爻 |
| 1 | 2 | 二爻 |
| 2 | 3 | 三爻 |
| 3 | 4 | 四爻 |
| 4 | 5 | 五爻 |
| 5 | 6 | 上爻 |

前端可以从上到下显示卦象，但不得改变存储顺序。API 中必须携带 `lineOrder: "bottom_to_top"`。

### 3.2 阴阳编码

- 阳爻：`1`
- 阴爻：`0`

例如乾卦表示为 `[1, 1, 1, 1, 1, 1]`，坤卦表示为 `[0, 0, 0, 0, 0, 0]`。

### 3.3 五行编码

内部使用稳定英文枚举，界面显示中文：

- `wood`：木
- `fire`：火
- `earth`：土
- `metal`：金
- `water`：水

### 3.4 天干地支编码

天干固定顺序：甲、乙、丙、丁、戊、己、庚、辛、壬、癸。

地支固定顺序：子、丑、寅、卯、辰、巳、午、未、申、酉、戌、亥。

地支五行：

| 地支 | 五行 |
| --- | --- |
| 寅、卯 | 木 |
| 巳、午 | 火 |
| 辰、戌、丑、未 | 土 |
| 申、酉 | 金 |
| 亥、子 | 水 |

## 4. 三枚铜钱起卦

### 4.1 铜钱计数

首版采用以下明确约定：

- 字面：2
- 背面：3
- 三枚铜钱相加得到 6、7、8 或 9

| 总数 | 名称 | 本卦 | 是否发动 | 变卦 |
| --- | --- | --- | --- | --- |
| 6 | 老阴 | 阴 | 是 | 阳 |
| 7 | 少阳 | 阳 | 否 | 阳 |
| 8 | 少阴 | 阴 | 否 | 阴 |
| 9 | 老阳 | 阳 | 是 | 阴 |

真实硬币没有清晰“字面、背面”时，界面应允许用户先指定哪一面计 2、哪一面计 3。指定后六次投掷期间不得改变。

### 4.2 投掷顺序

用户连续投掷六次：

1. 第一次为初爻。
2. 第二次为二爻。
3. 依次向上。
4. 第六次为上爻。

确认页面必须同时显示爻名和投掷序号，降低上下颠倒的风险。

### 4.3 随机模拟

随机模拟的每一爻等价于三枚公平铜钱独立投掷，因此四种结果的概率为：

- 6：`1/8`
- 7：`3/8`
- 8：`3/8`
- 9：`1/8`

实现时应模拟三枚独立二元结果，或使用完全等价的加权采样。不得把 6、7、8、9 设置为等概率。

随机来源必须使用运行环境提供的安全随机能力，不能使用模型生成的“随机数”。

### 4.4 手动录入

手动录入直接接收六个 6、7、8、9 数值。系统需要验证：

- 数组长度恰好为 6。
- 所有元素均属于 `{6, 7, 8, 9}`。
- 用户已确认输入顺序为初爻到上爻。

### 4.5 报数与时间起卦

`liuyao-chart-v0.1` 暂不定义报数起卦和时间起卦算法。网站首版不得用未版本化的临时公式生成六爻。

这两种方式以后分别使用独立的起卦规则版本，例如：

- `number-casting-v1`
- `time-casting-v1`

它们最终仍需输出标准的六个 6、7、8、9 数值，才能进入统一排盘流程。

## 5. 本卦与变卦

### 5.1 本卦阴阳

- 6、8 对应阴爻 `0`
- 7、9 对应阳爻 `1`

### 5.2 动爻

- 6、9 为动爻
- 7、8 为静爻

动爻位置以 1 至 6 表示，不使用零基下标对外展示。

### 5.3 变卦阴阳

- 6：由阴变阳
- 9：由阳变阴
- 7、8：保持本卦阴阳

即使没有动爻，系统仍可生成与本卦相同的 `changedHexagram`，同时标记 `hasChangingLines: false`。界面可显示“无变卦”或“之卦同本卦”，但数据层不得缺失。

## 8. 八宫归属

### 8.1 八宫顺序与五行

用于存储和测试的固定顺序为：

1. 乾宫，金
2. 震宫，木
3. 坎宫，水
4. 艮宫，土
5. 坤宫，土
6. 巽宫，木
7. 离宫，火
8. 兑宫，金

顺序只用于枚举和显示；它不改变卦宫判断结果。

### 8.2 八宫七变算法

每一宫从该宫的八纯卦开始，按以下方式得到宫内八卦：

| 宫内序号 | 类型 | 相对八纯卦发生变化的爻 |
| --- | --- | --- |
| 0 | 八纯卦 | 无 |
| 1 | 一世卦 | 初爻 |
| 2 | 二世卦 | 初、二爻 |
| 3 | 三世卦 | 初、二、三爻 |
| 4 | 四世卦 | 初、二、三、四爻 |
| 5 | 五世卦 | 初、二、三、四、五爻 |
| 6 | 游魂卦 | 初、二、三、五爻 |
| 7 | 归魂卦 | 五爻 |

引擎初始化时可以根据八个八纯卦自动生成全部 64 个宫位映射，并验证每个六位卦象只出现一次。

不建议在业务逻辑中手写多份互相独立的八宫表。

| 宫内类型 | 世爻位置 |
| --- | --- |
| 八纯卦 | 上爻（6） |
| 一世卦 | 初爻（1） |
| 二世卦 | 二爻（2） |
| 三世卦 | 三爻（3） |
| 四世卦 | 四爻（4） |
| 五世卦 | 五爻（5） |
| 游魂卦 | 四爻（4） |
| 归魂卦 | 三爻（3） |

### 9.2 应爻

应爻与世爻相隔三位：

- 世爻为 1、2、3 时，应爻分别为 4、5、6。
- 世爻为 4、5、6 时，应爻分别为 1、2、3。

一个卦中必须恰好有一个世爻和一个应爻。

## 10. 纳甲规则

### 10.1 基本规则

下卦负责初、二、三爻，上卦负责四、五、上爻。每个三爻卦根据其处于内卦还是外卦选择对应干支。

| 八卦 | 内卦天干 | 内卦地支（下到上） | 外卦天干 | 外卦地支（下到上） |
| --- | --- | --- | --- | --- |
| 乾 | 甲 | 子、寅、辰 | 壬 | 午、申、戌 |
| 震 | 庚 | 子、寅、辰 | 庚 | 午、申、戌 |
| 坎 | 戊 | 寅、辰、午 | 戊 | 申、戌、子 |
| 艮 | 丙 | 辰、午、申 | 丙 | 戌、子、寅 |
| 巽 | 辛 | 丑、亥、酉 | 辛 | 未、巳、卯 |
| 离 | 己 | 卯、丑、亥 | 己 | 酉、未、巳 |
| 兑 | 丁 | 巳、卯、丑 | 丁 | 亥、酉、未 |
| 坤 | 乙 | 未、巳、卯 | 癸 | 丑、亥、酉 |

### 10.2 本卦与变卦

- 本卦六爻全部装纳甲。
- 变卦也根据变卦自身的上下卦装纳甲。
- 用户界面默认只在动爻旁显示对应变爻信息，但数据中保留完整变卦六爻。

## 11. 六亲规则

### 11.1 判断基准

以本卦所属八宫的五行为“我”，根据每一爻地支的五行判断六亲：

| 爻五行与宫五行的关系 | 六亲 |
| --- | --- |
| 与我相同 | 兄弟 |
| 我生 | 子孙 |
| 生我 | 父母 |
| 我克 | 妻财 |
| 克我 | 官鬼 |

### 11.2 变爻六亲

变卦爻的六亲仍以**本卦宫五行**为判断基准，不重新使用变卦自身的卦宫五行。这保证“某爻化某六亲”的表达属于同一个占断坐标系。

## 12. 六神规则

### 12.1 六神固定循环

六神循环顺序为：

`青龙 → 朱雀 → 勾陈 → 螣蛇 → 白虎 → 玄武`

从初爻向上依次排列，到末尾后循环。

### 12.2 初爻起神

根据占测日的日干确定初爻六神：

| 日干 | 初爻六神 |
| --- | --- |
| 甲、乙 | 青龙 |
| 丙、丁 | 朱雀 |
| 戊 | 勾陈 |
| 己 | 螣蛇 |
| 庚、辛 | 白虎 |
| 壬、癸 | 玄武 |

系统内部统一使用“螣蛇”，搜索、导入或展示时可以兼容“腾蛇”别名。

六神只依据占测日干，不依据卦宫、动爻或用户问题改变。

## 13. 占测时间与历法

### 13.1 必填时间信息

每个卦盘必须保存：

- `castAt`：带偏移量的 ISO 8601 时间
- `timezone`：IANA 时区，例如 `Asia/Shanghai`
- `calendarRuleVersion`

不能只保存服务器时间，也不能根据服务器所在地推断用户时区。

### 13.2 v0.1 换日约定

第一版采用民用日期的零点换日：当地时间 `00:00` 进入下一日干支。

采用这一约定的主要原因是结果清晰、可复现，并与普通用户输入的公历日期一致。传统实践中存在子初换日等不同口径，因此系统必须显示并保存该约定。后续如增加 `23:00` 子初换日模式，应使用新的日历规则版本，不得改变历史卦盘。

### 13.3 月建

月建不用农历初一作为边界，而使用十二个“节”的精确交节时刻：

| 起始节气 | 月建 | 截止节气 |
| --- | --- | --- |
| 立春 | 寅 | 惊蛰 |
| 惊蛰 | 卯 | 清明 |
| 清明 | 辰 | 立夏 |
| 立夏 | 巳 | 芒种 |
| 芒种 | 午 | 小暑 |
| 小暑 | 未 | 立秋 |
| 立秋 | 申 | 白露 |
| 白露 | 酉 | 寒露 |
| 寒露 | 戌 | 立冬 |
| 立冬 | 亥 | 大雪 |
| 大雪 | 子 | 小寒 |
| 小寒 | 丑 | 立春 |

必须比较精确交节时间，不能只按节气所在的自然日切换。交节前仍属于上一个月建，交节时刻起属于新月建。

### 13.4 日辰

日辰包含日干和日支，由经过测试的历法模块根据当地民用日期计算。业务代码不得通过手写某个临时基准日公式重复计算。

选择历法依赖时必须满足：

- 支持公历日期到日干支。
- 支持精确节气时刻。
- 能明确控制时区和换日约定。
- 依赖版本固定。
- 使用独立参考数据建立边界测试。

历法库只负责计算，不能成为无法验证的唯一真相来源。

## 14. 旬空

旬空根据占测日干支所在的六甲旬计算：

| 六甲旬 | 旬空 |
| --- | --- |
| 甲子旬 | 戌、亥 |
| 甲戌旬 | 申、酉 |
| 甲申旬 | 午、未 |
| 甲午旬 | 辰、巳 |
| 甲辰旬 | 寅、卯 |
| 甲寅旬 | 子、丑 |

实现可以根据六十甲子索引计算，而不必只依赖查表：每旬十日，缺少的两个地支即为该旬旬空。

每一爻应保存 `isVoid`，表示该爻地支是否落入当日旬空。旬空是否“真空、假空、出空有用”属于占断层，不在排盘层直接下结论。

## 15. v0.1 暂缓字段

以下内容有价值，但不进入第一版基础排盘的完成门槛：

- 伏神与飞神
- 卦身
- 月破、日破和暗动结论
- 十二长生
- 三合、六合、六冲
- 进神、退神
- 反吟、伏吟
- 回头生、回头克的解释
- 应期自动判断

数据结构应允许以后添加这些派生状态，但不得为了预留而在 v0.1 输出未经实现的空泛结论。

其中伏神将在基础排盘通过固定案例验证后优先加入 `v0.2`。

## 17. 校验规则

生成正式卦盘前必须通过：

1. 恰好存在六个爻。
2. 爻位从 1 到 6 唯一且连续。
3. 本卦编码与 6、7、8、9 原始数据一致。
4. 变卦只在 6、9 所在爻位发生阴阳变化。
5. 本卦和变卦均能唯一映射到六十四卦。
6. 本卦能唯一映射到一个八宫位置。
7. 恰好存在一个世爻和一个应爻，二者相隔三位。
8. 每爻纳甲与其上下卦位置一致。
9. 每爻五行与地支一致。
10. 每爻六亲与本卦宫五行一致。
11. 六神排列与日干一致。
12. 旬空与日干支所在旬一致。
13. 月建与精确交节时间一致。
14. 所有正式字段均有明确规则版本。

任何一项失败，都应返回排盘错误，不能继续调用 AI 解读。

## 18. 测试要求

### 18.1 起卦测试

- 验证 6、7、8、9 的本爻、动静和变爻。
- 验证六次输入不会上下颠倒。
- 对大量随机结果验证 1:3:3:1 的概率趋势，但概率测试不作为逐次结果断言。

### 18.2 六十四卦测试

- 64 种六位编码全部能够唯一映射。
- 文王卦序 1 至 64 不重复、不缺失。
- 上下卦名称与六位编码一致。

### 18.3 八宫测试

- 八个宫各生成八个不同卦。
- 生成结果合计覆盖全部 64 卦且无重复。
- 每个宫内类型的世应位置正确。

### 18.4 纳甲与六亲测试

- 八个三爻卦分别测试内卦与外卦纳甲。
- 八个八纯卦用于检查宫五行和六亲。
- 变爻六亲始终使用本卦宫五行。

### 18.5 历法测试

- 十个日干分别验证六神起法。
- 六个六甲旬分别验证旬空。
- 十二个月建分别验证节气边界前一刻、交节时刻和后一刻。
- 当地时间 `23:59:59` 与次日 `00:00:00` 验证日辰切换。
- 同一 UTC 时刻在不同时区生成的当地日期应符合预期。

### 18.6 黄金案例

正式实现前至少准备：

- 8 个覆盖不同八宫的人工复核卦例。
- 4 个覆盖零动爻、单动爻、多动爻和六爻全动的卦例。
- 2 个位于节气交界附近的卦例。
- 2 个位于旬界附近的卦例。

黄金案例必须记录参考来源或人工复核人，不能只用本程序的输出来验证本程序自身。

## 19. 参考依据与工程说明
