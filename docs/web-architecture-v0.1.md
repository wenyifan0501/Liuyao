# 网页端架构与部署方案 v0.1

日期：2026-09-06。状态：目标架构；后端基础阶段已实施，尚未部署。实际已完成范围与运行方法见 [网页后端基础版本](./web-foundation.md)。

## 1. 范围与决策

面向创建者及少量受邀用户，提供以咨询为中心的响应式网页。措辞、占断规则和排盘继续由现有 Skill 与程序负责。页面采用历史咨询侧栏、中央对话、可展开卦盘；手机上侧栏和卦盘改为抽屉。

采用 React + TypeScript + Vite 前端、Fastify Node API、独立 Worker 和 PostgreSQL。一个仓库、同源访问、Docker Compose 单机部署。API 与 Worker 共用业务模块及构建镜像，通过不同启动命令运行。暂不引入 Redis、微服务或 Kubernetes。

选择原因：这是交互式私人咨询应用，首版不依赖搜索引擎收录或服务端渲染；现有 TypeScript 引擎适合直接接入 Node 服务。相比 Next.js 全栈方案，独立 Node 服务更贴近已有代码，长任务的生命周期也更明确。Next.js 同样可行，但本项目当前没有必须引入它的需求。

## 2. 组件职责

| 组件 | 选择 | 职责 |
| --- | --- | --- |
| 页面 | React、Vite、TypeScript | 消息、起卦卡片、卦盘、反馈、移动适配 |
| 路由及数据 | React Router、TanStack Query | 咨询地址、服务端状态缓存、刷新恢复 |
| 样式 | Tailwind CSS、基于 Radix 的组件 | 响应式布局、键盘操作、弹层、焦点管理 |
| API | Fastify | 登录、鉴权、输入校验、咨询操作、事件订阅 |
| 核心 | 现有 src/domain、calendar、ai、consultation | 排盘、解读、校验、同卦上下文 |
| 后台任务 | pg-boss + Worker | 持久任务、并发限制、失败处理 |
| 数据 | PostgreSQL + Drizzle 迁移 | 账户、咨询、卦盘快照、消息、任务与事件 |
| 网关 | Caddy | HTTPS、静态文件、API 与 SSE 反向代理 |

浏览器只使用公开 API 类型，不能从当前 src/index.ts 导入运行时模块，该入口包含 Node、Skill 文件读取和供应商代码。API Key 与 Skill 只部署在服务端。所有排盘以服务端结果为准。

## 3. 仓库组织

```text
apps/web/             前端及独立 tsconfig
apps/server/          HTTP API、鉴权、服务层
apps/worker/          AI 任务入口
packages/contracts/   公开请求、响应、事件类型与运行时校验
src/                  复用现有核心与 CLI，初期保留路径
Skill/liuyao/         原有六爻规则，不调整表达风格
Skill/{meihua,qiuqian,jiaobei}/  三种问事方式的解读 Skill，共用 Skill/shared/
schemas/              现有业务 Schema
db/                   数据定义与版本迁移
deploy/               Dockerfile、Compose、Caddy 配置
```

使用 npm workspaces。前端采用 bundler 模块解析，服务端沿用 NodeNext，分别执行类型检查。初期不为目录美观搬迁全部核心代码。容器构建必须包含 Skill 和 JSON Schema；Skill 路径显式配置，不能依赖偶然的工作目录。锁定经过现有测试验证的 Node LTS、依赖和数据库版本。

## 4. 表现层状态与流程

咨询阶段与生成任务状态分别存储。咨询阶段：draft → casting → chart_ready → active。任务状态：queued → running → succeeded / failed / cancelled；失败不清除已确认卦盘。

1. 创建咨询并保存问题、背景、时间范围和时区。未发送输入仅保存在页面状态，首版不默认把私人草稿长期写入浏览器存储。
2. 对话中的问题确认、起卦、卦盘均为显式类型的卡片，不通过解析 AI 文字判断应显示什么按钮。
3. 默认六次模拟投掷，提供一键完成、实体铜钱和手动录入入口。模拟投掷由服务端生成并保存，逐次请求含序号和幂等键；刷新或重复点击返回已有结果。
4. 确认时固定原始六爻、方式、时刻、时区及规则版本；服务端排盘并保存快照。纠正已确认数据创建有来源关系的新记录。
5. 创建解读任务，页面展示实际阶段；完成后开放同卦追问。
6. 追问期间同一咨询只允许一个活动生成任务，服务端通过事务与约束执行，不能只禁用前端按钮。
7. 历史咨询按问题命名，可继续交流、记录结果和删除。删除进行中的咨询须停止/失效化任务，禁止迟到结果重新写回。

现有 CLI 通过表单收集起卦前信息，没有完整的起卦前自由对话服务。首轮网页闭环先用聊天区域内的问题确认卡和可编辑背景字段接入；起卦前自由对话是后续服务层能力，不能仅靠表现层假装已实现。它可复用既有 Skill，但需要独立状态与输出协议，不纳入本次措辞修改。

## 5. 长任务与实时显示

POST 提交消息或启动分析后返回 202 与 runId。Worker 调用现有流水线，将任务状态、结果及适量合并的公开事件写入数据库。页面通过 GET /api/runs/:id/events 订阅 SSE。

公开事件至少有 status、text_delta、message_completed、failed；每条有单调事件序号、runId 和 messageId。事件流和最终查询都验证咨询归属。代理保持 SSE 及时刷新并定时发送心跳。

重连携带 Last-Event-ID；页面重载先读取任务和消息快照，再衔接事件。事件去重并以最终消息覆盖临时文本，不能重复追加正文。过期事件游标回退到快照同步。SSE 断开不取消后台任务；停止生成使用独立接口，并给 Gateway 增加可传播的 AbortSignal。

遵循现有程序的输出边界：

- 首轮结构化分析与纠错仅显示阶段状态，不发送内部 JSON 或 reasoning_content。
- 首轮 narrative 正文可增量展示，但完成前标记为生成中，不能当作已提交结果。当前校验针对结构化数据，并不等于自然语言正文逐项通过同等校验。
- 追问当前由 generateObject 返回，校验成功后一次展示 answer 与 nextQuestion；等待期间展示活动状态，不伪造逐字生成。
- 中断或失败的临时正文不可进入后续正式上下文。

当前 Gateway 单次调用默认超时 120 秒，首轮还包含纠错和正文阶段；任务总超时应结合实际调用次数配置，而不是沿用单次超时。队列设置租约/心跳与超时，重启后处理失联任务。队列重投可能再次调用供应商，不能承诺 API 计费恰好一次。

业务使用幂等键、任务版本及结果唯一约束避免重复消息和旧 Worker 覆盖新结果。任务入队与业务记录通过同一数据库事务或事务 outbox 协调。完整结构化结果可作为检查点，正文失败时优先从检查点重试，避免整套分析重新运行。

## 6. 持久化与账户

核心表：users、sessions、consultations、casting_drafts、charts、interpretations、messages、generation_runs、run_events、outcome_feedback。pg-boss 使用独立队列表。

咨询保存 ownerId、阶段和上下文版本；卦盘保存不可静默重算的 JSONB 快照与原始输入；解读保存模型、Skill 内容哈希、提示词版本和规则版本。消息、任务结果和更新后的上下文在事务中提交。现有本地 JSONL 是诊断日志，不作为网站数据库。

首版采用邀请制账户及成熟认证组件的服务端会话模式，使用 HttpOnly、Secure、SameSite Cookie。暂缓匿名永久历史、社交登录和找回密码邮件系统；具体认证库在实现时验证 Fastify 集成与维护状态后锁定。账号口令使用成熟库的安全哈希，不自行实现加密。

每个查询、修改和事件订阅均验证 ownerId；Cookie 写接口校验 Origin/CSRF。对登录、投掷和 AI 请求设置速率与并发限制。Markdown 禁用原始 HTML。生产日志采用 compact，不保存底层推理；业务历史仍按用户功能保存。删除涵盖相关事件及业务数据，备份中的数据按公布的保留期到期清理。

## 7. 推荐部署

第一阶段：一台 Linux 云服务器运行 Docker Compose，包含 caddy、api、worker、postgres 四个服务。前端构建产物放入 Caddy 镜像。

```text
浏览器 ── HTTPS ── Caddy ── 静态网页
                       └── /api/* ── API ── PostgreSQL
                                             ↑
                               DeepSeek ← Worker
```

以 2 vCPU / 4 GB 内存作为小规模内测的起始配置估算，Worker 先限制为 2 个并发任务；这不是容量保证，正式邀请用户前进行并发和长连接测试。模型运行在外部 API，不需要 GPU。

服务器地区应在购买前从候选区域实测用户访问和 DeepSeek 连通性。当前不绑定云厂商、不估算未经核实的月费，也不默认采购。域名指向服务器，开放 80/443，由 Caddy 管理 HTTPS；PostgreSQL 仅允许容器私网访问。数据库与证书使用持久卷，密钥通过受限服务端环境文件或密钥机制注入，不打包到镜像。

开发环境：本机 Vite + API + Worker，Compose 启动 PostgreSQL；Vite 将 /api 代理到 API。生产构建静态文件，不使用 Vite 开发服务器。

部署流程：检查与测试 → 构建版本化镜像 → 数据库备份 → 运行兼容迁移 → 停止 Worker 领取新任务并等待在途任务 → 更新服务 → 健康检查和登录/起卦/追问冒烟测试。镜像可以回滚；破坏性数据库迁移不能靠镜像回滚撤销，采用先扩展后清理的迁移策略。

自动每日加密备份到另一存储位置，建议保留 7 个日备份与 4 个周备份，并实际验证恢复。单机方案不提供高可用；数据库故障存在至最近可用备份之间的数据损失窗口。规模扩大后先迁移托管 PostgreSQL、增加 Worker，再考虑多实例 API 与共享事件通知。

## 8. 实施顺序与验收

1. 提取 CLI 编排为可复用服务，建立 API 协议、数据库迁移和账户隔离。
2. 完成新建咨询、输入确认、起卦、卦盘和历史查询，打通真实数据。
3. 接入持久任务、首轮解读、SSE、校验后追问、重试和刷新恢复。
4. 完成移动适配、结果反馈、删除、生产日志与 Compose 部署文件。
5. 部署测试环境，验证备份恢复后开放邀请内测。

必测场景：原有排盘测试继续通过；两个账户互不可见；重复提交不重复起卦/消息；分析时刷新可恢复；Worker 重启能收敛到明确状态；校验失败不发布追问答案；叠加请求不能覆盖同卦上下文；删除后迟到任务不能复活记录；真实 HTTPS 代理下 SSE 正常；数据库可从备份恢复。

## 10. 免费试用、收费与防滥用（商业方向补充）

用户已明确后续采用前几次免费、后续对话收费。此方向更新原产品需求 v0.1 的收费暂缓边界：支付接入可后置，但权益和用量控制必须进入首次公开试用版本。优先开源与低运营成本，不新建独立风控服务。

### 10.1 免费权益口径

免费额度不能按打开页面、创建咨询或消息条数由浏览器计数。建议定义一次试用为一份首轮解读加有限次追问；赠送咨询数 N、每次追问数 M 均服务端可配置，具体数值和收费价格尚未确定。首轮和追问可以有不同权益成本。起卦前 AI 交流如果上线，也必须限制轮次和消耗。纯程序排盘和查看已保存内容不触发模型调用。

所有模型入口统一经过鉴权、风险检查、权益预占、预算预占，再入队。正文 token 上限、上下文长度、纠错次数及任务并发都有上限；不能用无限长消息、无限起卦前交流或重试绕开免费限制。

### 10.2 分阶段防护

- 内测：一次性、限额、可撤销邀请码，领取绑定账户且不能转移；关闭无限公开注册赠送与邀请裂变赠送。低成本验证真实使用量。
- 公开试用建议：领取免费额度前验证手机号，一号一次领取，验证码具有短有效期、尝试次数限制及服务端安全存储；手机号只提高重复注册成本，不代表真实个人唯一身份。短信有费用，是否采用在公开上线时结合试用成本核算，不作为已经购买或接入的服务。
- 发短信前通过人机验证，按手机号、IP、第一方设备标识和全站总量限制发送，避免短信接口本身被刷；公开网页注册不直接赠送模型额度。
- IP 与可清除的第一方随机设备标识仅作风险信号，不能当作唯一身份。家庭、公司共享网络不直接永久封禁；异常时追加验证、冷却或人工复核。只信任配置好的反向代理提供的真实 IP，不能接受任意 X-Forwarded-For。
- 服务端领取记录有活动与身份的唯一约束，不能换浏览器重新领取；不默认永久保留已注销身份，相关最小化防重复标识须有明确保留期和告知。哈希后的手机号仍按敏感关联数据保护，采用带服务端密钥的摘要而非简单散列。
- 人机验证可评估 Turnstile 免费方案：这是第三方托管服务，不是开源自托管组件，接入前验证目标地区可用性。必须服务端验证 token、hostname 和 action；验证码只降低自动化滥用，不证明一人一号。通过适配接口保持可替换。

### 10.3 权益账本与成本预算

新增 trial_claims、entitlement_ledger、usage_reservations、usage_records、risk_events；支付上线再接 orders、payment_events。依靠 PostgreSQL 事务、唯一约束和行锁，无需首版增加 Redis。

请求使用幂等键原子预占权益与预算，并关联唯一 runId；成功提交一次有效结果后结算，失败释放用户额度。已经消耗的供应商费用仍记录到内部成本，不能随用户额度退还被抹去。失败请求也消耗频率预算；反复取消或故意触发失败进入冷却，避免免费退款循环。超时预占由后台核对任务状态后释放，不能仅凭时间直接释放仍在执行的任务。

设置全站免费调用每日预算和供应商总预算；每次实际模型调用（包括纠错）前检查预算，用输入估算及输出上限保守预留，返回 usage 后结算。供应商费用不明确的失败调用保留保守估算。阈值触发后暂停新免费任务、保留已付费任务的独立额度，并发送运维告警。不能只在请求结束后统计，否则并发会突破预算。

支付阶段只能根据服务端验签并核验金额、币种、订单归属的支付通知/主动查询入账，禁止浏览器支付成功跳转直接加余额。重复通知幂等处理，退款和撤销使用补偿账目。价格、支付渠道及商户接入条件另行确认，本次不执行支付接入。

### 10.4 补充验收

并发领取只成功一次；同一请求重发只预占一次；额度不足不能创建模型任务；Worker 重投不重复结算；失败和取消不能导致无限免费 API 调用；短信全局预算有效；共享网络正常用户有复核路径；全站免费预算耗尽后不再启动免费模型请求。

参考：[Turnstile 产品与免费方案](https://www.cloudflare.com/products/turnstile/)、[服务端 token 校验](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)。

本文描述目标架构，并非全部能力已经实现。后端基础阶段已新增 API、数据库迁移、账户隔离、排盘接口和内部权益账本；具体边界见 web-foundation.md。未创建云资源或进行部署。
